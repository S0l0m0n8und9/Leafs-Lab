# Leafs Lab Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development task-by-task. Ben explicitly requested delegated build execution.

**Goal:** Deliver a private Leafs Lab site with game, player and season analysis backed by reproducible imports.

**Architecture:** A Python pipeline emits a validated static JSON bundle. React consumes that contract; Sites hosts the production export.

**Tech Stack:** Python 3.11+, DuckDB when available, unittest, React, TypeScript, Vite, Node test tooling.

**Spec:** `docs/superpowers/specs/2026-10-12-leafs-lab-design.md`

## Global Constraints

- Missing data is null, never zero.
- Keep `all` and `5on5` rows separate.
- Calculations use full precision; display xG to two decimals, percentages to one, rates to two.
- Sample mode remains labelled on every view, including shared links.
- No AI inference, accounts, payments, betting advice, live xG, player photos or official logos.
- Exclude preseason/playoffs in v1 and do not join by display names.
- Do not imply the schedule is active simply because a workflow file exists.

## Review Focus

- Team totals and player rows from different providers/files must use normalized IDs without name joins.
- Zero ice time, missing xG and null numeric sort must remain absent values rather than misleading zeros.
- A failed fetch or validation must not overwrite last-known-good data or switch into sample mode silently.
- Strength and window controls must affect all displayed metrics consistently; outcome remains all-strength.
- Short windows and tied pre-shootout goals must not fabricate certainty or a win/loss.

## File Structure

`pipeline/`: provider adapter, calculations, exports and CLI. `tests/`: Python fixture/metric/import tests. `fixtures/`: illustrative CSV inputs. `public/data/leafs-lab.json`: validated generated bundle. `src/`: typed data layer, metrics/window helpers, shared chart primitives and four views. `docs/data-contract.md`: canonical JSON contract. `README.md`: setup/refresh. `.github/workflows/`: portable CI and prepared daily refresh. Controller owns `.openai/hosting.json`, registration, native source synchronization and deployment.
